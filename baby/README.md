# 👶 ベビー・ヘルスケア — 乳幼児の栄養・食事・成長記録アプリ

離乳期から幼児食までの**食事記録・栄養の過不足・成長曲線・アレルギー記録・生活リズム**を
1つにまとめたアプリ。加えて、1歳児特有の「少量しか食べないので食材が余る」問題に対して
**フードロスを増やさない使い切り献立**を提案する。

依存ライブラリなし・静的1ページで動作し、データは端末内（localStorage）にのみ保存される。

**公開URL: https://pchqk034-sudo.github.io/healthcare/baby/**

画面右上の **「🍱 大人用へ」** から、大人向けの
[ミール・ヘルスケア](https://pchqk034-sudo.github.io/healthcare/) に切り替えられる
（向こう側にも「👶 子ども用へ」がある）。データの保存先は別なので混ざらない。

## できること

### 📊 ホーム — 栄養の過不足
生年月日から月齢を計算し、**その月齢・性別の食事摂取基準**と当日の摂取量を比較する。
エネルギー・たんぱく質・**鉄**・カルシウム・亜鉛・ビタミンC・ビタミンD・食塩相当量を
バーで表示し、不足・過剰をルールベースのアドバイスとして出す。

食塩は「超えないこと」が目標なので、短いほど良い指標として扱う。

### ✍️ 記録
- 朝・昼・夕・おやつ別に食材を追加（食品DBから検索、1食目安量ワンタップ入力）
- ミルク・牛乳の回数と量、その他の水分
- 夜の睡眠と昼寝、排便の回数とようす
- 身長・体重（毎日でなくてよい。月1〜2回でも曲線は描ける）

食事に食材を追加すると、**在庫から自動でその分が引かれる**。

### 📈 成長 — 成長曲線とカウプ指数
身長・体重を**3〜97パーセンタイルの帯**とともにCanvasで描画し、カウプ指数
（体重kg ÷ 身長m²）から体格を判定する。帯から出ているかより、
**それまでのカーブから急に外れる変化**が大事な情報という見方を示す。

プロフィールに**出生時の体重・身長**を入れると、曲線が生まれた時から描かれ、
出生時と現在のパーセンタイル位置を比べて次を切り分ける。

| 判定 | 意味 |
|---|---|
| 出生時から一貫して大きめ／小さめ | もともとの体格に沿った推移。急な変化ではない |
| 位置が上／下に移動（30パーセンタイル以上） | 途中から傾向が変わった。健診で相談する価値がある |
| 位置がほぼ変わらない | もともとの体格を維持している |

グラフは**タッチまたはドラッグで記録点を選択**でき、選んだ点に赤い縦ラインが立って、
その時点の値・パーセンタイル・カウプ指数と、**その月齢の中央値／3%値／97%値・中央値との差**が
グラフ下に表示される。指を横に滑らせると選択が移動するので、推移を追いながら確認できる
（縦方向のページスクロールは妨げない）。

さらに**体重と身長のパーセンタイルが25以上離れている**場合は、
「身長に対して体重が重め／軽め」という形として指摘する。重めの場合は、
1〜2歳では減量ではなく「増加のペースが緩やかになって身長が追いつくのを待つ」のが基本で、
自己判断のカロリー制限は避けるべきことも併せて表示する。

なお健診で使われるのは**肥満度（身長別標準体重との比）**だが、公式の身長別標準体重表を
持っていないため、このアプリでは算出していない（概算で出すと誤誘導になるため）。
画面上でも「健診では肥満度で評価される」旨を案内している。

### 🍳 献立 — フードロス対策（このアプリの中心機能）
1歳児の1食は20〜80gと少量なので、にんじん1本（150g）は約7食分にもなり、
普通に買うと必ず余る。そこで在庫を起点に献立を組む。

1. **在庫を登録** — 食材・量・保存場所・期限。期限は未入力なら保存場所から自動補完
2. **期限が近い順に使い切る献立を生成** — 2/3/5/7日分
3. **結果** — 在庫の使い切り率、不足分だけの買い足しリスト、余る在庫の使い切り方

献立の選定ロジックは次を最適化する。

| 要素 | 効果 |
|---|---|
| 期限までの日数で重み付け | 期限切れ間近の食材から先に使う |
| 大人の料理から取り分け（👨‍🍳） | 味付け前に取り分けるので買い足しが不要 |
| 多めに作って小分け冷凍（🧊） | 使い切れない分を無駄にしない |
| 買い足し量にペナルティ | 新しく買う食材を最小化（主食・調味料は常備扱いで軽め） |
| 同日重複を禁止・直近ほど強く回避 | 朝昼夕に同じ料理が並ぶのを防ぐ |
| 摂取頻度の上限（レバー等） | 週あたりの回数を守る |
| 朝は調理時間の短い料理を優先 | 忙しい朝に15分の料理を出さない |

在庫が空でも献立は作れるが、その場合は買い物リストが長くなる。

### 📷 写真からの栄養推定
「記録」タブの各食事にある **📷 写真で解析** から、料理写真の栄養を推定できる。
大人向けアプリと同じ仕組みだが、乳幼児向けに次の点を変えている。

- **月齢をプロンプトに渡す**。1食の量が主食60〜90g・主菜15〜25g程度であることを明示し、
  大人の一人前と混同しないよう指示する
- **推定重量(g)も返させる**。返ってきた値を100gあたりに正規化して保存するので、
  量を手で直せば栄養も正しく再計算される
- **鉄・カルシウム・亜鉛・ビタミンC・ビタミンD** も推定させる（この時期に不足しやすい）
- **食塩が1日の目標の1/3以上ならバッジで警告**する
- **窒息リスクや加熱不足などの注意点**を返させる（丸ごとのぶどう・ミニトマト、ナッツ、
  この月齢には固すぎる形状、はちみつを含む可能性など）
- **特定原材料を推定**し、アレルギー記録の初回登録にも自動で反映する

解析した料理は**カスタム食材として保存され、次回から「＋ 食材を追加」の候補に出る**。
同じ手作りメニューを繰り返し作る場合、2回目以降は写真なしで記録できる。

使えるAIサービスは4つ。「設定」タブでキーを登録する。

| サービス | 特徴 |
|---|---|
| Google Gemini | 無料枠あり。まずはこれがおすすめ |
| Claude Sonnet | 精度と料金のバランスが良い |
| Claude Opus | 最も高精度。取り分け前後の判別など難しい写真向け |
| Claude Haiku | 安価だが精度は控えめ |

推定値なので、**量は必ず目で確認して調整すること**。キー未登録でも手入力での記録・分析・献立は
すべて使える。

### 💬 AI相談
お子さんの**月齢・成長の記録・今日の食事と栄養の過不足・冷蔵庫の在庫**を文脈として渡したうえで、
食事や生活リズムの相談ができる。「鉄を増やすには？」「野菜を食べてくれない」など定型の質問も用意。

回答の前提としてシステムプロンプトに次を入れている。

- 診断や治療の判断はせず、医療的な心配は小児科医・管理栄養士や乳幼児健診をすすめる
- 窒息リスク（丸ごとのぶどう・ミニトマト、ナッツ、豆、餅）、1歳未満のはちみつ、加熱不足に注意を促す
- 1〜2歳の食塩目標は3g未満で大人よりかなり厳しいことを前提に提案する
- レバーをすすめる場合はビタミンAの上限から3〜4g・週1〜2回までと明記する
- 体重が重めでも自己判断のカロリー制限はすすめない
- 記録の数値を根拠として引用し、一般論で終わらせない

### 🥕 食材 — 初めて食べた記録とアレルギー
食材ごとに初回摂取日・状態（試行中／OK／要注意）・症状メモを管理する。
特定原材料8品目の進み具合を一覧でき、保育園への申告や健診でそのまま見せられる。

初めての食材は**平日の午前中に1種類だけ・少量から**という原則を画面上でも案内する。

## 使い方

ブラウザで <https://pchqk034-sudo.github.io/healthcare/baby/> を開くだけ。
ローカルで動かす場合は `baby/index.html` を開く（またはリポジトリのルートを配信）。

1. 「プロフィール」でお名前・生年月日・性別を保存（月齢と基準値が自動で切り替わる）。
   **出生時の体重・身長**も入れておくと、生まれた時からの成長曲線が描ける
2. 「記録」で食事と生活リズムを入力
3. 「献立」に冷蔵庫の在庫を入れて、使い切り献立を生成
4. ときどき身長・体重を入れて「成長」で曲線を確認

## ☁️ 端末間でデータを共有する

夫婦2台のiPhoneなどで同じ記録を見られるようにする。サーバーは不要で、
**GitHubの非公開Gist**を保存場所にする。

1. **1台目**: 「設定」タブでGitHubトークンを登録 →「保存して今すぐ同期」→ 表示された**同期ID**を控える
2. **2台目**: **同じトークン**と、その**同期ID**を入力 →「保存して今すぐ同期」

トークンは <https://github.com/settings/tokens> で作成する。権限は **gist だけ**で足りる
（他は付けない）。有効期限も設定しておくと安全。Gistは非公開で作成される。

起動時と、記録を保存した数秒後に自動で同期する。「今すぐ同期」で手動実行もできる。

### マージのしかた

| データ | 扱い |
|---|---|
| 日々の記録 | 日付ごとに和集合。両方にある日は**更新時刻が新しい方**を採用 |
| 在庫 | idで和集合。削除は墓標を持たせ、同期で復活させない |
| 初めて食べた食材 | 名前で和集合。初回日は古い方、判定は確定している方を優先 |
| 写真から登録した食品 | 名前で和集合 |
| プロフィール・献立・相談履歴 | 更新時刻が新しい側 |
| **APIキー** | **同期しない**（Gistに置かないため、2台目で別途登録する） |

中身のない記録（画面を開いただけで作られる空の日）は、マージの際に存在しないものとして扱う。
これを勝たせると相手が入れた実データを空で上書きしてしまうため。

同じ日を2台で同時に編集した場合は、**後から保存した方がその日の記録を上書き**する。
起動時と保存後に同期が走るので競合する時間は短いが、同時編集は避けるのが確実。

**注意**: トークンはあなたのGistを読み書きできる。共有端末では使わず、gist権限のみ・期限付きで作成すること。

## データの扱い

- 記録はすべて端末のブラウザ内（localStorage）に保存される
- 外部へ送信されるのは、**写真AI解析・AI相談を使ったときの内容**（選んだAIサービス宛）と、
  **同期を有効にした場合の記録**（GitHubの非公開Gist宛）だけ。それ以外は端末内で完結する
- APIキーもlocalStorageにのみ保存される。ただしブラウザから直接APIを呼ぶ方式のため、
  **同じ端末を使える人にはキーが見える**。共有端末では使わないこと
- 「設定」からJSONで書き出し・読み込みができる。機種変更前に書き出しておくと安全
- ブラウザのデータを消すと記録も消えるため、ときどきの書き出しを推奨

## 数値の根拠と注意

| 項目 | 出典 |
|---|---|
| 栄養値 | 文部科学省「日本食品標準成分表」をもとにした概算 |
| 目標量 | 厚生労働省「日本人の食事摂取基準(2020年版)」 |
| 成長曲線 | 厚生労働省「乳幼児身体発育調査」をもとにした概算の参照値 |
| 食事の進め方 | 厚生労働省「授乳・離乳の支援ガイド」の一般的な目安 |

補足事項：

- **成長曲線の値は概算**である。月齢アンカー間は線形補間しており、正式な曲線は
  **母子健康手帳**を参照すること。数値は `data.js` の `GROWTH` にまとまっているので差し替え可能
- 食塩相当量は目標量（未満）、ビタミンDは目安量、他は推奨量にあたる値を使用
- 1〜2歳は食物繊維の基準が設定されていないため、その月齢では表示されない
- **レバーはビタミンAが約14,000µgRAE/100g** と非常に多く、1〜2歳の耐容上限量
  600µgRAE/日を5g程度で超える。アプリ側では既定量を3g・献立での登場を週1回までに制限し、
  上限を超える記録には警告を出す。鉄の補給は赤身肉・納豆・小松菜・きな粉を主役にするほうが安全
- カウプ指数の判定帯は一般的な目安であり、体格の個人差は大きい

このアプリは**記録と傾向の把握を助けるもの**で、診断や治療の判断には使えない。
発育や食事で気になることは、乳幼児健診や小児科医・管理栄養士に相談すること。
